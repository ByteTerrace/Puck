# C# ↔ HLSL sync pairs

The C# program model and the shader interpreter are one contract written twice.
Change either side only with its partner, in the same change. Back to
[../SKILL.md](../SKILL.md).

**The instruction set's values are generated; the rest is by hand.**
`src/Puck.SdfVm/Assets/Shaders/Sdf/isa/sdf-isa.hlsli` is generated by
`SdfIsaHlsl` (in `Puck.SdfVm.Model`, which compiles no shader) from the live C# model: every member of `SdfOp`, `SdfShapeType`, `SdfBlendOp`, `SdfLift`,
`SdfNoiseFlavor`, `SdfCellMode`, `SdfAxis`, `SdfPlane` and `SdfWallpaperGroup` (every enum an instruction lane
carries, the axis and plane selectors included), the header lanes as accessors (`SDF_INSTRUCTION_SHAPE(header)`,
`SDF_PROGRAM_MATERIAL_COUNT(header)`, `SDF_SEGMENT_COUNT(header)`, …) with the vector counts that place the headers
(`SDF_PROGRAM_HEADER_VECTORS`, `SDF_INSTRUCTION_DATA_VECTORS`, `SDF_BOUND_RECORD_VECTORS`,
`SDF_DIRECTORY_HEADER_VECTORS`), all from `SdfProgram`'s lane constants, which the packer writes through, and the
packed-layout constants marked *generated* below. A kernel reads a header lane only through its accessor and a
header's place only through the vector counts; `SdfKernelHeaderReadLawTests` refuses a swizzle or a literal
offset. An enum member's
HLSL name is its C# name in upper snake case after the enum's prefix
(`SdfOp.ResetPoint` is `SDF_OP_RESET_POINT`); a constant's HLSL name is listed
in `SdfIsaHlsl.Generate`. Never edit the file: change the C# and build. Every
generated declaration is in `ShaderDeclarations`' one list, which the kernel
projects' build-only reference `Puck.Shaders.Generator` writes before their
kernels compile and `puck shaders generate` writes by hand; a change that adds a
declaration and a kernel reading it builds in one pass. `puck shaders generate
--check` fails CI naming the file when it disagrees with the model. A new
ISA-owned constant or enum the kernels read joins `SdfIsaHlsl.Generate` rather
than a hand `#define`. Every numeric constant a kernel shares with C# is generated this way, the hash, mesh-record,
probe, transport, atmosphere, history, sky-environment and debug-mode constants included; a constant with no C# reader
stays a kernel `static const`. The generated vocabulary is two files: `sdf-isa.hlsli`, what the field interpreter
and the mesh bake read (the enums, lanes, layouts, the shapes' and hash's constants, the sampler filters, the
transform-slot sentinel), and `sdf-render.hlsli` (`SdfRenderHlsl`, from `SdfIsaHlsl.DeclareRender`), which includes
it and adds what the renderer alone reads (lights, exposure, the visibility record, mesh records, the irradiance
probe, temporal, glass, sky, atmosphere and debug-view constants). A renderer constant goes in the second, so it
moves no stored mesh's key; a field module includes only the first.

The operand lanes each case decodes, the hand-packed record lanes, and masks with
no C# constant are written on both sides by hand. Pass interfaces and native record
buffers generate their declarations through `ShaderInterfaceHlsl`; their host
writers must follow those same layouts. A kernel set
agrees with the instruction set it was built with because the build refuses
bytecode stale against its sources and every include (the generated
`sdf-isa.hlsli` among them), and `puck shaders generate --check` refuses a
stale generated file. The instruction set's fingerprint
(`SdfIsaHlsl.DescribeFingerprint`) hashes the include and the model's
described encoding (`SdfEncodingProbe.Describe`: one builder call per
operation, shape, blend, lift and lane-enum member, and calls packing every
side table and flag, described by each packed program's integer words and,
for each input raised alone, the bits of every integer word that moves and
every float word that moves; then, for each float word that moves, the input
that moves it most, or a tie when no input beats the next by half again), so
it moves when a field,
a bitfield, a header lane, a table entry or an enum value moves;
`SdfEncodingProbeLawTests` holds the probe to every member. `puck shaders
generate` records it in `SdfIsaFingerprint.cs`, which the host reads
(`SdfIsaFingerprint.Value`) rather than describing the encoding at boot. It is
the stamp the kernels' interfaces carry (`SdfWorldInterfaces.Stamp`, the `passGroup`
variable's name in `sdf-world.interface.hlsli` and `sdf-bricks.interface.hlsli`);
the bake's interface (`sdf-mesh-bake.interface.hlsli`) carries the field's
fingerprint instead (`SdfIsaFingerprint.Field`, `SdfIsaHlsl.DescribeFieldFingerprint`:
`sdf-isa.hlsli` and the encoding alone), so a renderer constant moves no bake key,
and every kernel's bytecode reflects the instruction set it was compiled against,
and a reload holds each changed kernel to the host's interface, stamp and
bindings (`SdfKernelSet.InterfaceMismatch`). `SdfFieldDeviceLawTests`
(`tests/Puck.World.Tests`, probe kernel `Assets/Shaders/sdf-field.comp.hlsl`)
runs the interpreter on Vulkan and Direct3D 12 hardware against
`SdfFieldEvaluator`, directly where it accepts a program and through an
equivalent at each point for the refused warps and displacements its oracles
describe; a new op the evaluator refuses gets an oracle there when one point
has an equivalent. Host-side law tests
(`PackLightsAndSkyLawTests`,
`WorldRenderEnvelopeLawTests`) pin only their C# half; `SdfFrameBlockLawTests`
holds the frame block's writer to the generated offsets, and
`SdfLightAndSkyLayoutLawTests` holds the lights and sky records, decoded through
their generated structures, to every value the kernels read.

C# symbols live in `src/Puck.SignedDistance` (the program model and its packed
records), `src/Puck.SdfVm.Model` (`SdfIsaHlsl`, `SdfKernelInterfaces`,
`SdfVisibility`, `ShaderDeclarations`), `src/Puck.SdfVm` (the residency, tables,
recorders, passes, meshes and kernel set) or `src/Puck.Shaders.Model/Graph`
(`SdfWorldPackage`); `puck declarations` names any one's file.
HLSL paths are under `src/Puck.SdfVm/Assets/Shaders/Sdf`. "Word" means a 32-bit
uint; "uint4" and "float4" name 16-byte vectors.

## Engine buffers, groups, and bindings

Native record buffers use `ShaderInterfaceStructure.From<T>()` to derive the
public unmanaged C# fields' offsets and stride. `ShaderInterfaceHlsl` emits the
struct and explicit padding; its reflected resource name carries the layout
identity so a same-stride field reorder rejects stale bytecode. The shared
interface echo reads two consecutive records prepared by
`ShaderInterfaceEcho.WriteRecordSentinels`, checking every field and the stride.
Keep record changes, generated includes, host region writes, and echo evidence
together.

| C# (`SdfWorldTables` unless noted) | HLSL | Contract |
|---|---|---|

## Shadow handoff storage

Shadow handoff records are `SdfShadowHandoff` in `Puck.SignedDistance`:
`Outgoing`, `Incoming`, `Slot` and `Weight` at byte offsets 0, 4, 8 and 12,
three signed integers and one float, stride 16. `SdfKernelInterfaces` derives
the HLSL structure and `sdfShadowHandoffs` World-group buffer from that record;
`SdfWorldTables.LightsAndSky.cs` writes active controls through the counted region.
The pass group carries the active count (`shadowFadeCount`) separately from
configured capacity, which `SDF_SHADOW_FADE_CAPACITY` bounds in
`frame/sdf-lights.hlsli`. A handoff allocates nothing: `shade/sdf-light.hlsli`
fades the outgoing light from its stable slot's K lane and lights the incoming
one unshadowed.

## Retained pass cadence

`ShaderPipelineResource.Retained` is an owned intermediate's single
queue-ordered allocation; do not combine it with transient, external, history
or public-output storage. A package recorder's nullable `Signature` authorizes
reuse only together with the node's input-generation and output-validity checks.
Keep `SkipAccesses` as the barrier-state path for both inactive and standing
passes; content generations are not a second barrier tracker.

Before setting `PreservesPredecessor` on a forwarding version, audit its actual
shader writes: it must preserve predecessor-owned fields and replace its own
fields idempotently. An accumulated counter or an overwritten sky image
violates that contract. A same-pass predecessor buffer read is legal only with
this validated retained package contract; the planned output remains a compute
read/write access. The package reads and writes through that writable binding,
not simultaneous SRV/UAV aliases. Keep the recorder's
binding, shader load alias and fragment output together. A later destructive
forward orders readers of all still-preserved ancestor versions before it.
An ordinary destructive forward or sampled image overlap is
still refused. Force a null signature for unversioned borrowed inputs
and for demanded work whose recording must run, including readback, capture
and temporal convergence. Existing dependency preparation retains its own
counting and ordering. `GpuPassState.Standing` has no per-pass count, so timing
or counted-load consumers must not interpret it as a measured zero.

A paused buffer producer publishes without a display surface. Keep its actual
last and previous named-output snapshots across an install, detach only owned
published ring slots into the existing held-resource retirement, and count their
bytes once. Do not expose unrendered replacement allocations or take ownership
of package-borrowed buffers. Their replaced package recorders retain the actual
owner while either publication names a borrowed allocation. An installed package
retaining the same buffer object takes over that owner obligation without holding
redundant old graphs; raw handles and external bindings do not. After actual
displacement, the existing reader lag and fence retire those recorders. The graph
never disposes the borrowed buffer directly. The reader lag retires displaced owned slots;
reset and device release withdraw both snapshots.
