# A portal as an indirect light source

The fixed camera observes a white floor beside a portal onto another world.
That destination contains a large red emissive wall. The root has no analytic
lights, emitting materials, sky radiance, fill or environment contribution.
Only the acquired screen source can bring red into its incoming floor lighting.

`fixture.puck` admits screens. `screens-off.puck` changes only that authored
gain to zero through the document basis. Both legs retain the same portal,
destination, camera, material and Medium cache. The script waits for the actual
current shared-cache source fence before its existing shared-pointer explanation
and screenshot. The manifest reads the screen category from that one fenced
floor answer and observes a central floor region; it never treats a screen's
host metadata or CPU color as acquired pixels.

The source is prepared and has not passed actual World qualification. The
48,48 pointer station and red image envelope must be confirmed on both
backends. The envelope distinguishes positive energy from black and independent
green or blue; it is not a numeric accuracy claim against the CPU reference,
which currently refuses captured screen pixels. Finite mutual closure,
immutable epoch pixels, cold capture history, external taint, nested budgets
and warmed crossing are separate required observations.
