# Puck.State.Rebuild.Corpus

The author-expression gate for the state system rebuild: every `.puck` source
this repository ships compiles clean, decompiles, and recompiles to the same
document, and every shipped world source compiles to the document beside it.

The rebuild is free to change every C# type and the lowered document shape
(rule 5). It is not free to change what an author wrote. This project holds the
corpus that says so, and every rebuild package runs it. It drives the
transpiler in process, so it needs no booted world and no GPU.

```
dotnet test tests/Puck.State.Rebuild.Corpus -c Release
```

The corpus is two trees, enumerated where they live rather than copied:

- `src/Puck.World/Assets/worlds/**/*.puck` — the shipped worlds, including the
  nine games decompiled from hand-authored JSON.
- `src/Puck.World.Transpiler/Samples/*.puck` — the transpiler's worked
  examples, the same top-level set `SamplesCompileTests` compiles. The
  `modules/` and `extensions/` subdirectories hold fragments, which are not
  root documents.

One source is excluded from the round trip and stays under the document gate:
`moth-courtyard.puck` expands to a document whose decompiled form is longer
than the parser's source limit, so the trip cannot close on it.
`ExcludedSourceDecompilesPastTheParserSourceLimit` fails if that stops being
true, which is how the exclusion retires.

The plan this serves is [the state system rebuild](../../docs/plans/state-rebuild.md).

  start, and the 9 decompiled games have no committed document — they are

  compiled with the checkout CLI first:
  `dotnet run --project src/Puck.Cli -c Release -- compile <path>`.
- **`.world.json` worlds** — the 9 decompiled games' documents plus
  `pipeline.world.json` (10 files), the documents that were hand-authored JSON
  before their `.puck` sources existed. The 9 now compile from those sources,
  and the compiler's output is canonically, not byte-identically, equal to the
  JSON these counts were taken from (member order and integral literal spelling
  differ), which preserves every discriminator and key this inventory counts.
  The nine are `backgammon`, `billiards`, `bowling`, `chinese-checkers`,
  `dominoes`, `hexlines`, `mancala`, `poker` and `tictactoe`;
  `chess`/`freecell`/`klondike`/`solitaire`/`spider`'s `.world.json` is
  compiler output already counted through their `.puck` source above, and
  `puck.world.json`, `modules/*`, and `shards/*` are outside this corpus (not
  named by the plan's acceptance corpus or by `CorpusSources.cs`).
- **Transpiler sugar fixtures** — `src/Puck.World.Transpiler/Samples/*.puck`
  (the 6 top-level fixtures `SamplesCompileTests` compiles, each compiled the
  same way) plus `tests/Puck.World.Transpiler.Tests/AuthoringSugarTests.cs`,
  read as source text (its fixture bodies are inline `.puck` fragments passed
  straight to the lowering pipeline, not files the CLI can compile standalone).

Counting method: for every `ActionEffect`/`ActionPredicate`/`StateTransform`/
`StateDomain` kind, a document's `"$type"` discriminators were walked
structurally (parsed as JSON, not text-matched) and counted per kind — the
same numbers a plain `grep -o '"\$type": "<kind>"' <files> | wc -l` reproduces
(verified to agree for every row below). A structural walk was used instead of
a bare grep because three discriminator strings — `all`, `any`, `not` — are
shared with `Puck.World`'s presentation-only `OverlayPredicate` (HUD/overlay
visibility, `src/Puck.World.Schema/WorldOverlayVisibility.cs`); the walk still
can't distinguish the two unions by text alone, so every corpus file was
additionally checked for any `OverlayPredicate`-only fact (`"$type": "speaking"
/"recently"/"near"`, or an `OverlayFact` name) and none were found — the
`all`/`any`/`not` counts below are `ActionPredicate` only. No other
discriminator this inventory counts collides with a second union anywhere in
`src` (checked by listing every `typeDiscriminator:` string in the repository
and confirming the ones below are unique, `all`/`any`/`not` aside).

Trait counts walk only each document's `"state"` subtree (structurally, same
reasoning) and count each candidate name's occurrences as an object's own
JSON key — `min`/`max`/`draw`/`phase` are common enough words that a bare
`grep` over the whole document would double-count unrelated fields elsewhere
(HUD, camera, physics); restricting the walk to `state` does not fully
resolve this (a `state.generators`/`state.patterns` entry could in principle
reuse `min`/`max` too), so treat `min`/`max` as an upper bound rather than an
exact figure. Operand spellings and authoring-sugar constructs are literal
`.puck`/JSON substrings and were counted with plain text search
(`str.count`, equivalent to `grep -o '<pattern>' <files> | wc -l`); the
pattern used is given above each table.

### Unresolved decision 1 — partial firing

**Does any shipped rule rely on partial firing?** Candidates were searched
for mechanically: every rule (across the 27 shipped documents scanned above,
380 rules total) with 2 or more top-level effects not already wrapped in one
enclosing `transaction`, where a later (non-first) effect is one the plan's
own examples name as refusable — `transformState` wrapping `transfer`,
`shuffle`, `arrange`, or `setRay` (full pile / empty or exhausted cursor) —
or, more broadly, `generate` (a redraw that can refuse the same way an empty
cursor does) or a nested `transaction` (whose own atomicity does not retroactively
cover a direct effect that already committed before it).

- **125 of the 380 shipped rules** author 2+ top-level effects outside a
  single enclosing `transaction`, excluding `games/reversi.puck`'s 120 flip
  rules (addressed on their own below, since none of them carries a
  `SetState` or `AddState`); every `SetState`/`AddState` write inside the
  other 125 can in principle refuse on a bounds violation (an authored
  `min`/`max` under the default `Overflow: Refuse`), so this is the true
  outer bound of exposure, not a list of confirmed bugs. None of
  `games/codenames.puck`, `games/pong.puck`, or `games/arena.puck`'s own
  multi-effect rules (11, 10, and 10 respectively) name a refusable non-first
  effect, so they add to this bound without adding a new candidate below.
- `games/reversi.puck`'s 120 flip rules each author eight `setRay` transforms
  outside a transaction, seven of which ordinarily refuse: a Reversi move
  brackets in one or two of the eight directions and the other rays accept no
  prefix. This is the corpus's one deliberate reliance on partial firing —
  each ray is its own boundary by design, and grouping them would refuse the
  whole move. The plan's own "full pile" / "empty cursor" examples still do
  not occur anywhere in the corpus. `reversi`'s other 6 multi-effect rules
  (`reversi-pass`, `reversi-place-black`, `reversi-place-white`,
  `reversi-reject`, `reversi-finish`, `reversi-score`) are plain `setState`/
  `addState` sequences with nothing refusable at a non-first position.
- **12 rules** are narrower, real candidates the lead should look at directly:

  | World | Rule | Effects (in order) | Refusable, non-first |
  |---|---|---|---|
  | `avatars/moth.puck` | `blink-open` | `setState`, `generate`, `setState` | `generate` (redraw) at index 1 |
  | `avatars/moth.puck` | `blink-close` | `setState`, `scheduleState` | `scheduleState` at index 1 — but `ScheduleState`'s only documented refusal (`DurationNotExactEngineTicks`) fires at rule-compile time, not runtime, so this one is unlikely to be a live case |
  | `games/poker.puck` | `poker-check-call` | `pushState`, `transaction` (7 inner effects) | the nested `transaction` at index 1 |
  | `games/poker.puck` | `poker-raise` | `pushState`, `transaction` (8 inner effects) | the nested `transaction` at index 1 |
  | `games/poker.puck` | `poker-fold` | `pushState`, `transaction` (7 inner effects) | the nested `transaction` at index 1 |
  | `games/poker.puck` | `poker-showdown` | `setState`, `setState`, `transaction` (6 inner effects) | the nested `transaction` at index 2 |
  | `games/stratego.puck` | `stratego-red-move` | 3 × `setState`, `removeStateCell`, 4 more | `removeStateCell` at index 3 — refuses when the row carries no cell at that key, so the board writes before it would stand alone |
  | `games/stratego.puck` | `stratego-blue-move` | the same shape | `removeStateCell` at index 3 |
  | `games/stratego.puck` | `stratego-red-strike` | 2 × `setState`, 2 × `transformState` (`observe`), 2 × `setState`, 2 × `if`, 4 more | `transformState` at index 2, and the `removeStateCell` effects inside each `if` branch |
  | `games/stratego.puck` | `stratego-blue-strike` | the same shape | the same |
  | `games/snake.puck` | `snake-eat` | 2 × `setState`, `pushState`, `setState`, `if`, `addState`, 2 × `setState`, `generate`, `setState` | `generate` (the next food's draw) at index 8 |
  | `games/snake.puck` | `snake-spawn` | `transformState` (`boardCombine` clear), 3 × `pushState`, 9 × `setState`, `transformState` (`push`), 3 × `setState`, `generate`, `setState` | `generate` (the first food's draw) at index 17 |

  In each `poker` case, if the nested `transaction`'s own preflight refuses
  any of its inner effects, none of the transaction's effects apply, but the
  `pushState`/`setState` effect(s) authored before it already did — the
  transaction's atomicity does not extend backward to cover them. This is
  the clearest evidence of authored (if likely unintentional) reliance on
  partial firing in the corpus. The four `stratego` rules are the same shape
  with a removal in place of the nested transaction: the piece's board square
  is already cleared when its rank cell's removal is the effect that refuses.
  The two `snake` rules read the same way `moth`'s `blink-open` does: a
  refused redraw leaves the writes before it committed. Snake's own
  food-placement rules recover from that on the next tick, since they re-read
  the board rather than trusting the draw, but the exposure is the same shape.

None of the four card games besides poker (`chess`, `freecell`, `klondike`,
`solitaire`, `spider`), the remaining 8 decompiled games, `hearts`,
`codenames`, `pong`, `arena`, or `reversi`'s own rules beyond its flip
pattern show this pattern; `stratego` and `snake` do (above).

### Unresolved decision 2 — literal conversion

**How many authored comparisons put a fractional literal against an Int
cell?** Zero. Every `ActionPredicate.CompareState` whose `value` is
non-integral, and every `ActionPredicate.CompareValue` with `kind: "Int"`
whose `left`/`right` text contains a fractional literal, was found across
all 27 shipped documents and cross-referenced against each document's

Fourteen fractional-literal `compareState` comparisons do exist in the
