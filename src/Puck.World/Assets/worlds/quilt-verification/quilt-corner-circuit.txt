# Quilt border-crossing evidence — the WHOLE-CIRCUIT proof Wave 1's own deliverable asks for: one continuous walk,
# one body, crossing all four zones and returning to its start, no loading, no restart. Prior evidence
# (quilt-{nw,ne,sw,se}-walk.txt, quilt-nw-liveness.txt) only proves eight PAIRWISE crossings in isolation — never
# a circuit, which can fail in ways a pairwise crossing cannot (accumulated drift, a latch that never clears, an
# instance that reaps under it, a cohort that desyncs). This script is that missing proof.
#
# ROUTE: nw(boot) -[door-to-ne]-> ne -[door-to-se]-> se -[door-to-sw]-> sw -[door-to-nw]-> nw. A FULL LOOP, not a
# literal figure-eight: the quilt's borders are strictly orthogonal pairwise pairs (nw|ne, ne|se, se|sw, sw|nw) —
# no diagonal portal exists between nw|se or ne|sw, so a path that self-crosses AT the corner post has nothing to
# cross through. A loop that traverses every zone once and closes back on its starting ZONE is the strongest proof
# this content can express.
#
# Run: dotnet run --project src/Puck.World -c Release -- --world src/Puck.World/Assets/worlds/quilt-nw.world.json
#   --exit-after-seconds 18 --state-dir <fresh-tmp-dir> < this-file
#
# HISTORY. At integrate-wave1 d267d3d1 this script could not run at all: every quilt door authors marginDepth, and
# WorldDefinitionLoader's boot-time validation pass always calls the validator with neighbours: null (DI/storage
# don't exist yet), which ValidateMarginStrips refuses unconditionally — no quilt zone could boot via --world, in
# any environment. Lane L7 fixed this at 9591536a (a file-backed IWorldNeighbourResolver ahead of the storage one)
# — this script is verified AT THAT FIX, cherry-picked onto it. quilt-{nw,ne,sw,se}-walk.txt and
# quilt-nw-liveness.txt, authored before the neighbour-resolver requirement ever landed, describe arrival numbers
# that no longer match (see the table below) — read them for the RECIPE pattern, not the numbers.
#
# THE FULL CROSSING TABLE (measured against the real, committed, unmodified quilt documents; one continuous body;
# wire.errors 0 rejected at every checkpoint):
#   Leg 1 nw(boot) -> ne  : world.transfer arrival (-0.41, 0.02, -12.00) yaw=270 -- z held exactly continuous
#     (started and landed at z=-12.00); instance-qualified re-read: (-0.16, 0.02, -12.00) -- +0.25 coasting drift
#     under the kit's own deceleration curve, the liveness signature quilt-nw-liveness.txt established (proof the
#     destination instance is live-ticking, not stalled).
#   Leg 2 ne -> se        : arrival (12.00, 0.02, -0.41) yaw=180 -- x held continuous (12.00 -> 12.00); re-read
#     (12.00, 0.02, -0.16).
#   Leg 3 se -> sw        : arrival (0.41, 0.02, 12.00) yaw=90 -- z held continuous (12.00 -> 12.00); re-read
#     (0.16, 0.02, 12.00).
#   Leg 4 sw -> nw        : arrival (-12.00, 0.02, 0.41) yaw=0 -- z held continuous (2.00 -> arrival); re-read
#     (-12.00, 0.02, 0.16).
# wire.errors read 0 rejected after every single leg.
#
# THE CLOSING LEG LANDS IN 'boot'. Relative references now resolve beside the SOURCE INSTANCE's own document before
# preview and traveler resolution share their canonical identity. That keeps eager door previews live without
# mistaking AppContext's copied Assets tree for a second origin: ne's preview of nw adopts the already-running boot
# instance, and the real leg-4 crossing reuses that adoption. The final bare `player.where 1` below is the law — it
# would refuse and increment wire.errors if the traveler were ever deposited in a parallel nw instance again.
#
