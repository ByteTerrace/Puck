# ROM ledger

This plan gives the engine's verification ROMs the treatment branding received:
one home, a hashed manifest, one `puck` verb that checks it, and a CI gate. Today
the repository reaches ROM images through about nine unrelated mechanisms, and
the only thing keeping a licensed image out of Git is a `*.gb` line in
`.gitignore`. The plan also retires the Tetris tooling that grew up around a
commercial reference cartridge.

House cartridges are product content, not verification ROMs. They move with the
official product under [Product content](product-content.md).

## Implementation status

Reviewed against `ef148e667`. Nothing has landed.

## Owner decisions

- **The Tetris cartridge keeps its game and becomes `tetromino`.** Tetris is a
  trademark with no generic name the way chess has one; a tetromino is the
  mathematical name for its four-square pieces. The authored cartridge and its
  real execution tests stay, and every tie to the commercial
  `tetris-world-rev1.gb` is cut: no comparison tool, no reference path, and no
  ledger entry for that image.
- **Every house cartridge has a `.puck` source.** `pip.agb` gets one by
  decompiling its document; `puck decompile` followed by
  `puck compile --validate` reproduces the committed document byte for byte.
- **Licensed images remain usable as Post evidence, recorded by hash only.**
  Retail BIOS images, the AGS aging cartridge, and the link, trade, and solar
  games stay available to the emulator batteries. The ledger records each one's
  id and SHA-256. Their bytes never enter the repository.
- **`roms/` holds the engine's verification ROMs.** Those are house boot ROM
  records, public test corpora, and licensed images. Cartridges live in the
  product that ships them.
- **The plan comes before the implementation.** Work proceeds in the slices
  below, and each slice deletes whatever it replaces in the same squash.

## What exists today

ROM-shaped content falls into eight categories. Each one is found or obtained in
its own way:

| Category | Where it is | How code finds it |
|---|---|---|
| House boot ROMs | 14 `.bin` files in `src/Puck.HumbleGamingBrick/Firmware`, `puck-agb.bin` in `src/Puck.AdvancedGamingBrick/Firmware` | Embedded resources, regenerated by `puck firmware` |
| House cartridges | `tetris.cgb`, `hgb-mirror.cgb` (source and document), and `pip.agb` (document only) in `src/Puck.World/Assets/cartridges` | Document-relative `content.path`, plus hard-coded paths in test files |
| Generated test ROMs | Built in memory by Post, the forge, and a few tests | No lookup needed |
| Public test suites | `corpora.json` in each Post project (four archives) | `CorpusManifest` with a local cache and `--roms`, `--sst`, `--fuzz` overrides |
| Licensed cartridges | Supplied by the developer | `--games`, `--ags`, `--accuracy-suite`, `--link-game`, `--solar-rom`, `--link-rom`, `--trade-rom` |
| Retail boot images | Supplied by the developer | `--bios`, cosimulation `--boot <dir>`, the engine's `bios=` option, `firmware.path` |
| Local `roms/` folder | Git-ignored; holds `tetris-world-rev1.gb` and ad hoc exports | `TetrisSideBySide` default path and a five-level `../` path in `hgb-compare.puck` |
| Tetris tools | `TetrisExport`, `TetrisLook`, `TetrisShots`, `TetrisSideBySide` | Environment variables (`PUCK_TETRIS_*`) |

Several inconsistencies follow from that spread:

- `--boot` accepts only `puck` in `Diagnostics.cs` but a directory in `CosimDiagnostic.cs`.
- The AGS cartridge is reachable both through `--ags` and as a fixed filename under `--games`.
- The corpus manifests carry no license, and CI's cache key hashes each battery's file separately.
- `.gitignore` re-includes `verification/authority/fixtures/*.gb`, a directory that no longer exists.
- `docs/emulation/agb/test-roms-and-evidence.md` and `docs/development/contributing.md` document `PUCK_AGB_*` variables that no code reads.
- `ComprehensiveSyntheticTests` uses a made-up `roms/tetris.agb` path.
- Every ROM-related test walks up to `Puck.slnx` with its own private copy of the loop, although `build/RepositoryPaths.cs` exists.

The four Tetris tools are `[Fact]` methods that return early unless an
environment variable is set. They report as passing without running anything.

## Design

### One home

A tracked `roms/` directory at the repository root holds `manifest.json`, with
the schema id `puck.roms.v1`, and a README that answers "where is this ROM,
where did it come from, and how do I update it?"

House boot ROM images stay beside the source and license that produce them.
Their packages embed them from there, and the ledger records their hashes.

### Ledger entries

Every entry has an `id`, a `kind`, and a `sha256`. The kind determines the other
fields:

| Kind | Bytes in Git | Additional fields |
|---|---|---|
| `firmware` | Yes, beside its source | `path`, `license`, `generator` (the `puck firmware` target that rebuilds it) |
| `corpus` | No; fetched into the local cache | `version`, `archive` URL, `root`, `license`, `homepage` |
| `external` | Never | `description`, accepted hashes, and the Post stages that use it |

Corpus entries replace both `corpora.json` files. `CorpusManifest` is the
existing fetch-and-cache mechanism, so it is extended to read the ledger rather
than paralleled by a second reader.

External entries resolve from one local store beside the corpus cache, keyed by
id. A developer places an image there once. The battery refuses an image whose
hash matches no accepted value and names the entry. The per-image Post flags
collapse into that lookup.

### The `puck roms` verb

`puck roms` follows the `puck branding` contract: every check runs before
anything is written, exit code 1 reports one line per problem, and `--check`
never writes.

- `--check` verifies the manifest shape and every tracked hash.
- `fetch` downloads and verifies corpora. It replaces each battery's `--fetch-corpora`.
- `locate <id>` prints where an entry resolves, or why it does not.

The check also scans in reverse, which branding does not. Any tracked file with
a ROM extension, or a valid Game Boy or Game Boy Advance header, that neither the
ledger nor a product manifest names fails the check. For branding a stray copy is
untidy; for ROMs it is the line between house content and someone else's.

`verify.yml`'s `ledgers` job runs `puck roms --check` with the candidate CLI.
The corpus cache key hashes `roms/manifest.json`.

### One resolver

Tests, Post, and tools look verification ROMs up by ledger id through one public
resolver, and cartridges through the product root that ships them. Nothing
outside those two assembles a path to a ROM, walks to the repository root, or
reads an environment variable for a ROM location.

## Slices

Each slice lists the conditions that complete it.

### 1. Retire the eclipsed tooling

Delete `TetrisExport` (replaced by `puck compile` and `forge.export`), plus
`TetrisLook` and `TetrisShots` (replaced by `forge.play` and `capture.start`;
cartridges are verified in a world). Delete `TetrisSideBySide`, `hgb-compare.puck`,
and its ignored generated document. Remove the stale `verification/authority`
rule from `.gitignore`, the unread `PUCK_AGB_*` documentation, and the made-up
`roms/tetris.agb` path.

Move `CartridgeCostMeasurement` out of the test project into a `puck` verb,
keeping its bisection method. Update the rom-forge skill's re-measurement
instructions.

Done when `puck search -M 0 PUCK_TETRIS` and `puck search -M 0 tetris-world`
return nothing, no test in `tests/` returns early on an environment variable,
and the forge test projects pass.

### 2. Ledger, verb, and corpora

Create `roms/manifest.json` and its README with `firmware` and `corpus` entries.
Add `puck roms` with `--check`, `fetch`, and `locate`. Point `CorpusManifest` at
the ledger, add license fields, delete both `corpora.json` files, and update the
Post READMEs, `docs/emulation/hgb/post-and-conformance.md`, and
`docs/emulation/agb/test-roms-and-evidence.md`. Wire the check and the cache key
into `verify.yml`.

Done when `puck roms --check` passes on the checkout and fails on each seeded
defect (hash drift, missing file, unregistered ROM), both batteries fetch through
the verb, and the `ledgers` job runs it.

### 3. Cartridges join the official product

This slice rides with slice 2 of [Product content](product-content.md). Move the
cartridges into `content/puck/cartridges` and name them in its manifest. Commit
`pip.agb.puck` beside its document, make the round-trip gate in
`CartridgeRoundTripTests` enumerate cartridges from product manifests, and delete
the rom-forge and puck-dsl skills' note that `pip.agb` has no source. Replace the
hard-coded cartridge paths in tests with the product root.

Done when the round-trip gate covers all three cartridges from the product
manifest and the official world boots with every arcade cabinet inserted.

### 4. Rename the Tetris cartridge

Rename `tetris.cgb` to `tetromino.cgb`: the source, document, tests, and every
prose reference, including `docs/plans/retail-scale-cartridges.md` and both
skills. The rename changes the cartridge's content hash; re-record anything that
pins it in the same change.

Done when `puck search -M 0 -i tetris` returns nothing outside Git history and
`experimental/`, and the cartridge's execution tests pass under the new name.

### 5. External images and one lookup

Add `external` entries for every licensed image a Post stage accepts, and the
local store. Replace `--bios`, `--games`, `--ags`, `--accuracy-suite`,
`--link-game`, `--solar-rom`, `--link-rom`, `--trade-rom`, and both `--boot`
spellings with ledger ids. Stages that need a missing image skip with the entry's
id rather than a flag name.

Done when no Post project declares a per-image path flag, both batteries run
their asset-free lanes unchanged, and a stage given an image with an unaccepted
hash refuses it by entry id.

## Open questions

- **Where `tetromino` belongs.** With `hgb-compare` gone, no world uses it; only
  forge tests and cartridge documentation do. Decide whether it becomes an arcade
  cabinet in the official product or a test fixture.
- **The engine's `bios=` option and `firmware.path`.** These are player-facing
  inputs for their own images, not repository content. The ledger probably should
  not govern them; confirm that during slice 5.
- **Visual resemblance.** Renaming removes the trademark, not the cartridge's
  likeness to the commercial game it was tuned against. Review its presentation
  in slice 4.
