# Author-shaders design review

Findings only. Source review of the memo, research/citation checks and current implementation; no build, World, GPU measurement or tier-equivalence experiment was run. The cases below identify design gaps, not observed failures of an implemented shade VM. No tracked file was edited, staged or committed.

## Findings

1. **High — The surface hook can invalidate shadow decisions already made.** Memo: §3.1, §3.2 (`docs/plans/author-shaders.md:359`, `:383`, `:427`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-surface-stage.hlsli:354`, `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-views-stage.hlsli:135`, `src/Puck.SdfVm/SdfWorldTables.Cadence.cs:119`. The surface pass queries shadows using the base material's wrap and the original normal; views filters those answers before the proposed hook changes wrap/normal. A base-wrap-zero surface whose program raises wrap can become lit on a side for which no shadow was queried. The unqueried slot is treated as visible. **Fix:** define an enforced conservative shadow-demand envelope derived from the program, or evaluate the required response before shadow estimation. Carry that dependency into surface cadence. Include a shadowed back-facing surface and an animated normal/wrap in the design's checks.

2. **High — Cel migration requires the supposedly optional light hook.** Memo: §3.1, §3.9, steps 6–7 (`docs/plans/author-shaders.md:366`, `:631`, `:766`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/shade/sdf-light.hlsli:247`, `:264`; `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-light-stage.hlsli:200`, `:220`, `:268`. Cel banding consumes each light's cosine and visibility, changes specular response, and has post-light composition. A pre-light function producing albedo/roughness/etc. cannot reproduce this for two differently directed lights. Deleting banding in step 6 therefore either loses cel or leaves an engine implementation beside authored programs. **Fix:** specify the light-response and necessary composition interfaces before migrating cel, and move their required implementation ahead of step 6. Keep only neighbour-reading outline machinery outside that authored response.

3. **High — The proposed views-only ABI cannot migrate glass flow.** Memo: §3.1–3.2, §3.9 (`docs/plans/author-shaders.md:359`, `:416`, `:637`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-glass.comp.hlsl:259`, `:272`; `src/Puck.SdfVm/Assets/Shaders/Sdf/shade/shade-flow.hlsli:89`; `worlds/standard/water.puck:45`. Glass calls the shared flow implementation per interface, supplying contact coverage; flow also transforms velocity through the mesh draw's carry when there is no frame slot. The proposed stamp exposes neither contact nor that draw-space transform, and execution is only in opaque views. Removing `SdfFlow`/its HLSL would break authored water or force another implementation. **Fix:** define a shared surface-program invocation for opaque and glass shading, with the needed generic frame/contact inputs. Include glass invocations in specialization, costing, dispatch bounds and quarantine; exercise contact foam and transformed copies before deleting the old layer.

4. **High — One generated table does not prove an invisible numerical swap.** Memo: §3.4, §4 (`docs/plans/author-shaders.md:502`, `:520`, `:677`). Code: `src/Puck.Shaders.Model/Compiler/ShaderCompiler.Identity.cs:46`; `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-views-stage.hlsli:127`; `src/Puck.SdfVm.Model/SdfIsaHlsl.cs:59`; `src/Puck.Cli.Shaders/GenerateCommand.cs:34`. DXC receives `-O3`; separate interpreter iterations and straight-line specialized locals expose different folding/contraction opportunities. A small arithmetic difference feeding `step` or a hash can become a full colour change. Generated-file comparison proves text provenance, and the existing ISA fingerprint proves layout/encoding agreement, not numerical equivalence. Microsoft documents this contraction distinction in [HLSL variable syntax](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-variable-syntax). **Fix:** define float precision, contraction, constant-folding, integer/bitcast and exceptional-value semantics in the IR; enforce them in both generated paths. Stamp transitive semantic dependencies too. Add threshold-sensitive and boundary-value comparisons on both targets; a meadow still is insufficient evidence for all admitted programs.

5. **High — The named memory-safety door does not enforce the claimed range.** Memo: §3.3, §4 (`docs/plans/author-shaders.md:471`, `:662`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/field/sdf-program.hlsli:6`, `:12`, `:16`; `src/Puck.SignedDistance/SdfAppearance.cs:446`. `sdfProgramRange` checks the entire `sdfWords` allocation, not one shade program's subrange. Existing paint side-table pointers are absolute addresses. An incorrectly relocated descriptor can point into another material/program while passing that check. The memo also does not specify register initialization, operand typing or index validation. **Fix:** make the sealed program own validated relative ranges and typed register operands; validate use-before-definition and all descriptors during construction. Route shader reads through a slice-aware reader, including shape helper reads. Keep the final whole-buffer check as an additional boundary, not the ownership proof.

6. **High — Static cost is not yet closed over builtin work.** Memo: §3.2, §3.7, §4 (`docs/plans/author-shaders.md:431`, `:447`, `:591`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/field/sdf-shapes.hlsli:253`, `:675`, `:683`, `:701`; `src/Puck.SignedDistance/SdfPaint.cs:104`; `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-light-stage.hlsli:185`. Unrolling source loops does not unroll or price the loops inside `shape`: an admitted sweep can traverse strands, samples and refinement rounds, unlike a sphere. “One op with a declared cost” is sound only if that cost bounds the complete helper or depends conservatively on validated operands. Program cost also excludes the surrounding light walk and interpreter overhead, so it cannot price every instruction in the shade dispatch. **Fix:** define the counted unit and transitive cost functions, including branches, helper loops and loads/taps. Distinguish logical per-pixel work from wave execution and fixed pass overhead. Use checked arithmetic and establish `MaxOps <= MaxWork`. Any future texture op needs explicit sampling/filter/LOD and tap bounds before admission. Keep the memo's correct qualification that work is not elapsed time.

7. **High — The hard bound and quarantine disappear on the documented fallback; dispatch is also confused with submission.** Memo: §3.5, §3.7–3.8, §4 (`docs/plans/author-shaders.md:570`, `:599`, `:612`, `:682`). Code: `src/Puck.SdfVm/SdfWorldPassRecorder.cs:720`; `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-pixel-entry.hlsli:7`; `src/Puck.Shaders/ShaderPipelineRenderNode.Work.cs:163`; `src/Puck.SdfVm/SdfWorldResidency.cs:776`. If binning loses, the memo retains the unsplit views kernel, but the sole enforcement door and quarantine attribution name views-shade bins. The existing unsplit recorder dispatches the whole extent; its filter requires intact groups. Separately, multiple bounded dispatches can share one command-list submission, so the asserted largest submission is not bounded by `MaxWork`. **Fix:** design bounded scheduling and in-flight identity tracking for both architectures before selecting one, including whole-group units for unsplit views and glass from finding 3. Either bound aggregate submissions too or remove that claim. Retain quarantine identities outside disposed GPU tables, clear only changed program identities, and exercise loss on both paths. Whole-program-set specialization also needs its own set identity and invalidation rules; it cannot retain the claimed one-kernel-per-program edit behaviour unchanged.

8. **High — Program identity and editable parameters contradict each other.** Memo: §3.2–3.4, §7 (`docs/plans/author-shaders.md:405`, `:481`, `:504`, `:797`). Code: `src/Puck.SignedDistance/SdfAppearance.cs:406`, `:419`; `src/Puck.SdfVm/Assets/Shaders/Sdf/shade/shade-flow.hlsli:86`; `src/Puck.Shaders.Model/Compiler/ShaderCompiler.Identity.cs:72`. The example supplies seed, colour, settle and scale as template arguments; calls are inlined, constants propagated, and constants enter program identity and specialized code. Changing a seed consequently changes the executable unless a separate parameter-lowering rule exists. No schema for those arbitrary parameters replaces the deleted layer rows. **Fix:** distinguish runtime parameter slots from structural constants before canonicalization; include parameter layout in executable identity and values in appearance data only. Define explicit structural parameters such as octave count. Check that changing a seed/colour preserves stream identity, kernel and bin, while a structural edit changes them.

9. **High — Authored inputs lack dependency metadata for upload and cadence.** Memo: §3.2, §3.9 (`docs/plans/author-shaders.md:416`, `:637`). Code: `src/Puck.SignedDistance/SdfAppearance.cs:120`, `:127`; `src/Puck.SdfVm/SdfFrameBlock.cs:253`, `:258`; `src/Puck.SdfVm/SdfWorldTables.Cadence.cs:59`. Today clock and world lanes are supplied only when hard-coded material-layer inspection says they are read. Delete those records and a shade-only animation receives zero clock/world lanes. Keeping them always live instead makes static worlds redraw needlessly. **Fix:** derive input-read metadata from canonical programs and aggregate it through appearances into frame upload and cadence signatures. Derive it from actual reads, never template names such as `flow`. Check an otherwise static clock-driven program, a world-lane-only program, and a program reading neither.

10. **Medium — Reusing reload installation does not provide a stall-free specialization swap.** Memo: §3.4, step 3 (`docs/plans/author-shaders.md:512`, `:742`). Code: `src/Puck.SdfVm/SdfWorldTables.Pipelines.cs:113`, `:117`, `:120`; `src/Puck.SdfVm/SdfKernelTreeLoad.cs:29`. Existing installation waits for GPU idle, forgets environment/screen-emission work, and advances geometry as well as program revisions. Doing that whenever one material finishes compilation creates a render-thread wait and unrelated work. The tree loader also enumerates fixed `SdfKernel` entries, not authored identities. **Fix:** extend the shared cache/loader to dynamic identities; publish a ready specialization for the matching program/semantic generation without content invalidation, and retire the replaced pipeline after its last submission fence. Measure a burst of completions and an edit overtaking an older compile, not merely two settled stills.

11. **Medium — Filter output ownership is unspecified at the binning boundary.** Memo: §3.5 (`docs/plans/author-shaders.md:547`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-views-stage.hlsli:37`, `:54`; `src/Puck.SdfVm/Assets/Shaders/Sdf/frame/sdf-visibility.hlsli:39`; `src/Puck.Shaders.Model/Graph/SdfWorldPackage.cs:257`. The eight-word visibility record has no spare two-word output area. If “write ... into the visibility record” reuses its AO/shadow words, one group's store can race a neighbouring group's apron gather; the group barrier does not order those groups. Appending fields is safe but must update allocation, strides and every consumer. **Fix:** explicitly preserve immutable raw filter inputs and allocate distinct filtered fields/storage, with graph access declarations and barriers to scatter/shading. Specify filtered precision and include the extra bytes/traffic in step 4. If separate fields were intended, state that invariant rather than leaving it to implementation convention.

12. **High — Steps 2 and 4 do not yet decide whether the complete design meets the bar.** Memo: §3.4–3.5, §6 (`docs/plans/author-shaders.md:535`, `:734`, `:752`, `:758`, `:766`). Code: `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-light-stage.hlsli:132`; `src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-views-stage.hlsli:107`; `src/Puck.World/WorldPopulationCommandModule.cs:134`. Step 2 executes the weathering slice, while the remaining combined programs migrate after the performance decision and after `MaxWork` calibration. It explicitly mandates action for a Deck failure but leaves other failures and a too-slow cold interpreter unresolved. Step 4's “worst frame is better” does not specify per-device acceptance or cover zero authored programs, sparse/tiny bins and mixed pending/specialized programs. An empty-authored frame still pays interpreter register allocation when unsplit, or classification/scan/scatter/storage if the split is unconditional. **Fix:** define a per-device/backend decision matrix using the memo's chosen frame metric and the 60/60/45 bar, explicit regression/noise criteria, and a rule when neither architecture passes. Measure zero/one/many programs, cap-cost programs, mixed cold tiers, nested views and the final migrated set. Define the no-program dispatch/allocation path and price every added pass, byte and recording operation. Calibrate work margins from adversarial admitted programs. Assign the GPU evidence in steps 1, 3, 5 and 6 as GPU work too; those steps are incorrectly labelled headless/CPU.

## Where I found no independent defect

- **Fixed compute pipeline state, within the stated hook.** `GpuPassPipelineKey.OfCompute` (`src/Puck.Shaders/Pipeline/GpuPassPipelineKey.cs:45`) and the shared description (`src/Puck.SdfVm/SdfWorldTables.Pipelines.cs:146`) support one description per authored views executable. Raster cull/depth state and formats are engine-owned (`src/Puck.SdfVm/SdfMeshRasterPass.cs:128`, `:152`). View extent, temporal mode and other view controls are pass values (`src/Puck.Shaders.Model/Graph/SdfWorldPackage.cs:292`); native/reconstructed/temporal views use declared package variants (`src/Puck.Shaders.Model/Graph/SdfWorldPackage.Resolve.cs:70`). I found no hidden authored blend/depth/format multiplier in this fixed views ABI. This is not proof that the entire world's pipeline count equals its shade-program count: engine passes, targets and the additional hooks still exist, and the set-specialization fallback needs the identity work in finding 7.
- **Appearance separated from bake inputs.** `src/Puck.SdfVm/Assets/Shaders/Sdf/field/sdf-program.hlsli:79` and `src/Puck.SdfVm.Model/SdfIsaHlsl.cs:70` support excluding shade-only appearance data from field identity. Field-shared helper changes must still invalidate the bake; the claim applies to program/data edits, not arbitrary shader edits.
- **Derived shader cache reuse.** `src/Puck.Shaders.Model/Compiler/ShaderCompiler.Identity.cs:72` includes source closure and compile steps; `src/Puck.Shaders.Model/Compiler/ShaderCompiler.Entries.cs:18` checks entry identity and payload digest. I found no reason to introduce a separate shader-bytecode cache.
- **Barrier placement and simulation separation.** Keeping the spatial gather/filter before pixel reordering is correct (`src/Puck.SdfVm/Assets/Shaders/Sdf/passes/sdf-views-stage.hlsli:117`). A read-only presentation stamp with only surface outputs introduces no simulation write path. These positive conclusions do not establish the missing filter-storage, numerical or memory-slice contracts above.
